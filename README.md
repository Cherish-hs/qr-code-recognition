# OpenCV 实时二维码与条形码识别系统

基于 Python、OpenCV 和 Pyzbar 的本地摄像头识别工具，支持图像增强、EAN-13 校验、多帧确认、历史记录去重、CSV 记录和现场截图。包含有效 HTTP/HTTPS 网址的二维码经过多帧确认后，会自动请求默认浏览器打开。

识别结果除写入 CSV 和截图外，还可以**可选地**通过 MQTT 实时推送给其他系统。该功能默认关闭，未启用或连接失败都不影响识别与保存，详见第 7 节。

## 快速开始

目标机器装好 Python 3 和 `libzbar0` 后，在项目根目录执行：

```bash
./install.sh
./run.sh
```

所有可调参数（摄像头编号、保存路径、多帧确认阈值、是否自动打开网址、MQTT 开关）都在 [src/config.py](src/config.py)，普通用户无需改动其他源码。Windows 与 macOS 的依赖差异见 3.5 节。

## 1. 主要功能

- **实时识别与标注**：读取摄像头画面，为通过业务验证的条码绘制识别框并显示类型和内容。
- **图像增强**：灰度化后进行 CLAHE 局部对比度增强，再调用 Pyzbar 解码。
- **分类校验**：EAN-13 检查长度、数字格式及校验位；二维码只接受有效 HTTP/HTTPS 网址；其他可解码条码类型不做额外业务校验。
- **多帧确认**：相同类型和内容在最近最多 5 帧中至少出现 4 次，才进入网址打开与保存流程。
- **历史去重**：启动时读取已有 CSV，已保存的同类型、同内容条码不重复保存，重启后仍生效。
- **记录与截图**：保存识别时间、条码类型、完整内容，以及当前画面的 JPG 图片。
- **网址自动打开**：合格二维码达到确认条件后自动请求打开网址，同一次运行中相同网址只尝试一次。可在配置中关闭。
- **窗口内状态提示**：被过滤、已记录过、已保存时，画面左上角显示对应提示，避免"扫了没反应"的困惑。
- **可选 MQTT 推送**：开启后把新记录以 JSON 发布到 MQTT 主题；默认关闭，不开启时程序完全离线运行。

当前版本会跳过普通文本二维码，不提供按 `o` 打开网址的操作。按 `q` 退出程序。

## 2. 技术栈与模块结构

| 技术 | 用途 |
| --- | --- |
| Python | 主流程与业务逻辑 |
| OpenCV（`cv2`） | 摄像头采集、灰度化、CLAHE 增强、画框、窗口显示和图片保存 |
| Pyzbar / ZBar | 二维码与条形码检测、解码 |
| `collections.deque` | 保存最近 5 帧的识别结果 |
| `csv`、`os`、`datetime` | 历史记录读取、文件保存和时间生成 |
| `urllib.parse`、`webbrowser` | URL 格式解析和默认浏览器调用 |
| paho-mqtt（可选） | MQTT 客户端，仅在开启 MQTT 推送时使用 |

除 OpenCV、Pyzbar、paho-mqtt 外，其余模块均为标准库，无需单独安装。paho-mqtt 只在开启 MQTT 推送时才会被使用。项目不需要训练模型、下载模型权重或配置数据库。

## 3. 环境准备

需要可用摄像头、图形桌面环境和 Python。网址打开功能还需要系统默认浏览器。以下以 Ubuntu 为例。

### 3.1 获取项目

```bash
git clone https://github.com/Cherish-hs/qr-code-recognition.git
cd qr-code-recognition
```

以下步骤对应包含上述 `src/` 目录的模块化版本，请确认交付或检出的版本包含这 7 个源码文件。

### 3.2 安装系统依赖

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip libzbar0
```

如果需要使用 MQTT 推送（默认关闭），再安装 Mosquitto。安装后它会作为系统服务自动运行，可用 `ss -tln | grep 1883` 确认已在监听：

```bash
sudo apt install mosquitto mosquitto-clients
```

Linux 上，Pyzbar 还需要系统提供 ZBar 动态库，不能只安装 Python 包。部分发行版使用带 `t64` 后缀的库包名，请以系统实际提供的包为准。

如果导入 OpenCV 时提示缺少 `libGL.so.1`，再执行：

```bash
sudo apt install libgl1
```

### 3.3 创建虚拟环境并安装 Python 依赖

在项目根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

`requirements.txt` 内容为：

```text
opencv-python>=4.8
pyzbar>=0.1.9
paho-mqtt>=2.0,<3
```

本程序需要窗口显示，应安装 `opencv-python`。无图形界面的 `opencv-python-headless` 不能直接满足当前程序的运行需求。

`paho-mqtt` 只用于可选的 MQTT 推送。代码在未安装该库时会自动跳过 MQTT 功能，不影响识别。版本必须为 2.x，因为实现使用了 `CallbackAPIVersion.VERSION2`。

整理文档时，工作区环境为 Python 3.12.3、opencv-python 5.0.0.93、pyzbar 0.1.9、paho-mqtt 2.1.0；这些是环境记录，不是最低版本要求。

### 3.4 验证安装

```bash
python -c "import sys; print(sys.executable)"
python -c "import cv2; print(cv2.__version__)"
python -c "from pyzbar.pyzbar import decode; print('Pyzbar / ZBar OK')"
```

解释器应指向当前虚拟环境，两个库均应能够正常导入。此步骤尚未验证摄像头和图形窗口。

### 3.5 其他系统

- **Windows**：可用 `py -3 -m venv .venv` 创建环境，PowerShell 使用 `.\.venv\Scripts\Activate.ps1` 激活；再安装相同的 Python 依赖。若 ZBar DLL 加载失败，需根据报错检查 Python 架构和运行库。
- **macOS**：通常需要先安装系统 ZBar，例如执行 `brew install zbar`，并授予终端或 IDE 摄像头权限。

其他系统的说明为安装参考，尚未逐个平台实测。

## 4. 启动与操作

在项目根目录执行任一方式：

```bash
# 方式一：脚本启动（推荐）
./run.sh

# 方式二：手动激活虚拟环境
source .venv/bin/activate
python src/main.py
```

识别窗口左上角会显示当前状态：`RECORDED`（已保存）、`ALREADY RECORDED`（历史中已有）、`URL QR ONLY`（二维码不是网址）、`INVALID EAN13`（校验位不通过）。这些提示只作用于画面，不影响保存逻辑。

程序首先加载历史记录，然后通过 `cv2.VideoCapture(CAMERA_INDEX)` 打开默认摄像头，显示“条码识别”窗口。多摄像头设备可在 [src/config.py](src/config.py) 中修改 `CAMERA_INDEX`。

1. 将清晰、完整的条码放到摄像头前，保持适当光照和距离。
2. 通过业务验证的结果会显示绿色框和类型、内容标签。
3. 达到多帧确认条件后，新条码保存图片与 CSV；有效网址二维码还会自动请求浏览器打开。
4. 点击识别窗口使其获得焦点，按 `q` 退出。

例如，可以使用内容为 `https://example.com` 的二维码联调网址流程；普通文本二维码会被过滤。

当前模块采用同目录导入，请使用上述启动方式（`./run.sh` 或从 `src` 目录启动）。保存路径由 `src/config.py` 中的 `BASE_DIR` 计算为项目根目录，与启动位置无关。

## 5. 识别与确认规则

### 5.1 图像处理

`scanner.py` 的处理顺序为：

```text
摄像头 BGR 画面 → 灰度图 → CLAHE 增强 → Pyzbar 解码
```

CLAHE 参数为 `clipLimit=2.0`、`tileGridSize=(8, 8)`。解码使用增强后的灰度图，标注和保存使用原始彩色画面。

### 5.2 EAN-13 校验

条码必须为 13 位数字。将前 12 位从左到右按 `1、3、1、3……` 加权求和，计算：

```text
校验位 = (10 - 加权和 % 10) % 10
```

结果必须与第 13 位一致。例如 `6901234567892` 校验通过。该规则检查编码结构，不查询商品信息或判断商品真伪。

### 5.3 二维码 URL 验证

二维码内容先去除首尾空白，再检查：

- 协议为 `http` 或 `https`。
- 存在主机名。
- 处理后的字符串内部没有空白字符。

通过后返回网址，否则跳过该二维码。此检查仅筛选格式，不验证网站是否可访问或可信。

### 5.4 最近 5 帧中至少出现 4 次

每帧使用集合保存 `(条码类型, 原始内容)`，再将集合加入 `deque(maxlen=5)`；没有识别结果的帧也加入空集合。

同一个码在单帧中最多计数一次。窗口内累计至少 4 帧出现才确认，**不要求连续 4 帧，也不需要等满 5 帧**：前 4 帧都出现时，第 4 帧即可确认。确认按帧计数，实际耗时随帧率变化。

### 5.5 保存去重与网址去重

| 状态 | 初始化方式 | 作用 |
| --- | --- | --- |
| `seen_codes` | 启动时从 CSV 加载，保存成功后更新 | 避免同类型、同内容重复保存，支持跨重启去重 |
| `opened_urls` | 每次启动为空集合 | 避免同一网址在本轮运行中重复尝试打开 |

网址打开逻辑在保存去重之前执行。因此，历史中已有的网址二维码在重启后重新确认时，仍会尝试打开浏览器，但不会再次保存记录。

## 6. 保存格式

### 6.1 CSV 记录

默认文件为 `pyzbar_records.csv`：

```csv
识别时间,条码类型,识别内容
2026-10-22 14:00:00,EAN13,6901234567892
2026-10-22 14:00:03,QRCODE,https://example.com
```

以上为格式示例。时间使用运行机器的本地时间，文件编码为 `utf-8-sig`，便于表格软件显示中文。条码数字建议按文本列导入，避免表格软件自动转换格式。

程序启动时按“条码类型”和“识别内容”字段恢复去重集合。历史 CSV 不存在时从空集合开始，已有记录不会被覆盖。

### 6.2 JPG 截图

图片默认保存在 `pyzbar_images/`，文件名包含微秒，例如：

```text
20261022_140000_123456.jpg
```

保存的是调用 `cv2.imwrite()` 时的当前全画面，可能包含识别框和文字，不是条码裁剪图。显示标签截取前 50 个字符，CSV 保存完整解码内容。

程序先保存图片，再追加 CSV，只有两步都成功才把条码加入内存去重集合。图片成功但 CSV 失败时，图片仍会保留，之后可能再次尝试保存。

## 7. MQTT 实时推送（可选）

MQTT 是可选输出通道，默认关闭。不开启时程序完全离线：识别结果只写入本地 CSV 和截图。

### 7.1 什么时候需要开启

只有"另一个程序需要**实时**收到识别结果"时才需要，例如局域网看板、数据库写入服务或报警系统。它不承担存储职责，历史仍由 CSV 和截图保管。

### 7.2 开启步骤

1. 在本机安装并启动 Mosquitto（见 3.2 节）。
2. 修改 `src/config.py`，把 `MQTT_ENABLED` 改为 `True`。
3. 启动程序，终端会输出 `【MQTT】已连接 127.0.0.1:1883`。
4. 另开一个终端**先订阅**，再扫码：

```bash
mosquitto_sub -h 127.0.0.1 -t 'opencv/barcode/result' -v
```

### 7.3 消息格式

主题 `opencv/barcode/result`，QoS 1，payload 为 JSON：

```json
{"barcode_type": "QRCODE", "content": "https://example.com", "timestamp": "2026-10-31T17:00:55+08:00"}
```

时间戳带本地时区偏移，由发布时刻生成。

### 7.4 重要限制

- **不保留历史**：默认 `MQTT_RETAIN = False`，订阅者必须在消息发布前就在线，否则消息直接消失。
- **只推送新记录**：与历史 CSV 重复的条码不会发布。
- **默认无认证**：Mosquitto 默认只监听 `127.0.0.1`，本机任意进程都能匿名订阅 `#`。多人共用电脑时建议配置账号密码。
- **失败不影响主流程**：连接失败会自动跳过 MQTT，识别、截图和 CSV 照常进行。

### 7.5 相关配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `MQTT_ENABLED` | `False` | 总开关 |
| `MQTT_BROKER_HOST` / `MQTT_BROKER_PORT` | `127.0.0.1` / `1883` | Broker 地址 |
| `MQTT_TOPIC` | `opencv/barcode/result` | 发布主题 |
| `MQTT_QOS` | `1` | 至少一次 |
| `MQTT_RETAIN` | `False` | 是否保留最后一条 |
| `MQTT_CLIENT_ID_PREFIX` | `opencv_barcode_publisher` | 实际 ID 会自动附加随机后缀 |

## 8. 常见问题

| 问题 | 排查方法 |
| --- | --- |
| 找不到 `cv2` 或 `pyzbar` | 检查虚拟环境和解释器，使用同一个 `python -m pip` 安装依赖 |
| 找不到 ZBar 动态库 | 安装系统 ZBar 库，Ubuntu 通常使用 `libzbar0` 或对应发行版包 |
| OpenCV 缺少 `libGL.so.1` | Ubuntu 安装 `libgl1` |
| 窗口无法显示 | 检查是否安装 headless 包，以及当前是否有可用图形桌面 |
| 没有检测到摄像头 | 检查连接、设备编号、权限和其他程序是否占用摄像头 |
| 有画面但不识别 | 检查对焦、距离、反光和条码完整性；确认二维码不是被过滤的普通文本 |
| 有框但没有新增记录 | 检查是否达到 4/5 条件、历史是否已有记录，以及终端保存错误 |
| 保存目录不符合预期 | 记录文件与截图目录默认固定在项目根目录下，可在 `src/config.py` 中修改 |
| 浏览器打开失败后不重试 | 当前实现每轮对相同网址只尝试一次，检查默认浏览器配置 |
| 按 `q` 无反应 | 让识别窗口获得焦点，并切换到英文输入 |
| 终端提示 `【MQTT】未启用` | 正常现象，MQTT 默认关闭；需要时在 `config.py` 中打开 |
| 终端提示 `【MQTT】连接失败` | 检查 Mosquitto 是否安装并在监听 1883；失败时其余功能不受影响 |
| 订阅不到 MQTT 消息 | 必须在识别之前启动订阅；该条码也不能已存在于 CSV 中 |

## 9. 验证情况与当前限制

整理文档时，已在当前虚拟环境中验证 EAN-13 校验、URL 验证、生成二维码的扫描解码、JPG/CSV 写入和历史重新加载。真实摄像头、图形窗口和默认浏览器仍需在目标桌面环境中联调。

MQTT 部分已在本机验证三种情况：未启用时正常降级并继续运行；broker 不可达时打印提示但不中断；broker 可达时成功提交，payload 时间戳带时区偏移。

当前实现还有以下边界：

- 多帧确认只能减少部分偶发识别，不能保证结果一定正确。
- 确认依据整个历史窗口，没有要求该码仍在当前帧，截图可能已经不包含刚离开画面的条码。
- 图片与 CSV 分开写入，不具备事务性；CSV 中尚未保存图片路径。
- 网址在调用浏览器前加入 `opened_urls`，打开失败后同轮不会重试；打开请求成功也不代表网页加载成功。
- 原始内容与历史加载时的首尾空白处理存在差异，可能影响特殊内容的去重。
- 字节内容按 UTF-8 解码，无法解码的字节使用替代字符；OpenCV 内置字体对中文标注支持有限。
- 所有可调参数集中在 `src/config.py`，修改配置需编辑该文件，暂不提供图形配置界面。
