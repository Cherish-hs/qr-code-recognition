# OpenCV 实时二维码与条形码识别系统

基于 Python、OpenCV 和 Pyzbar 实现的摄像头实时二维码与条形码识别工具。支持识别结果显示、EAN-13 条形码校验、连续多帧识别确认、CSV 记录、识别图片保存，以及二维码网址打开。

## 1. 项目简介

本项目通过电脑摄像头实时获取图像，使用 Pyzbar 检测并解码画面中的二维码和条形码，再通过 OpenCV 将识别结果显示在实时画面中。

为减少摄像头画面抖动、条码遮挡等因素造成的误识别，程序会统计最近 5 帧的识别结果。当同一个条码至少在其中 4 帧出现时，才会保存对应的识别记录。

项目适合 Python、OpenCV 入门学习，也可以作为后续扩展图像识别、目标检测和自动化记录功能的基础。

## 2. 主要功能

- **实时识别：** 调用电脑摄像头，持续检测二维码和条形码。
- **识别结果可视化：** 在画面中绘制识别框，并显示条码类型和内容。
- **EAN-13 校验：** 检查 EAN-13 条形码的长度、数字格式及校验位。
- **多帧确认：** 最近 5 帧中至少 4 帧识别到同一个码，才允许保存记录。
- **去重处理：** 使用集合记录已处理的条码，避免同一个条码重复保存。
- **CSV 日志：** 记录识别时间、条码类型和识别内容。
- **图片保存：** 将识别时的摄像头画面保存为 JPG 图片。
- **网址识别：** 检查二维码内容是否为有效的 HTTP 或 HTTPS 网址。
- **快捷操作：** 按下 `o` 打开最近识别到的有效网址，按下 `q` 退出程序。

## 3. 技术栈

| 技术                  | 主要用途                  |
| ------------------- | --------------------- |
| Python              | 编写程序逻辑                |
| OpenCV (`cv2`)      | 摄像头读取、图像处理、绘制识别框及显示窗口 |
| Pyzbar              | 检测和解码二维码、条形码          |
| `datetime`          | 生成识别时间和图片文件名          |
| `collections.deque` | 保存最近 5 帧的识别结果         |
| `os`                | 检查文件、创建目录及拼接文件路径      |
| `csv`               | 将识别结果写入 CSV 文件        |
| `webbrowser`        | 调用默认浏览器打开网址           |
| `urllib.parse`      | 解析网址并检查协议和主机名         |

其中，`datetime`、`collections`、`os`、`csv`、`webbrowser` 和 `urllib.parse` 均属于 Python 标准库，不需要单独使用 pip 安装。

```bash
cd qr_barcode_project
```

激活后，终端通常会在命令提示符前显示 `(.venv)`。

```bash
python -m pip install -r requirements.txt
```

在 Ubuntu 上，Pyzbar 还需要系统级的 ZBar 动态库。

```bash
sudo apt update
```

如果使用 Ubuntu 24.04，以上命令通常可以满足基本运行需求。

```bash
python -c "import cv2; print(cv2.__version__)"
```

```bash
python -c "from pyzbar.pyzbar import decode; print('Pyzbar 安装成功')"
```

## 6. 运行程序

确认已经激活虚拟环境，并且摄像头可用。

```bash
python test_pyzbar_code.py
```

程序启动后，会打开一个名为“条码识别”的实时画面窗口。

将二维码或条形码放在摄像头前，程序会自动检测并显示识别结果。

首次满足多帧确认条件的条码会被保存到 CSV 文件中，同时保存对应的 JPG 图片。

## 7. 操作说明

| 按键  | 功能                       |
| --- | ------------------------ |
| `o` | 打开最近识别到的有效 HTTP/HTTPS 网址 |
| `q` | 退出实时识别程序                 |

注意：

- 按下 `o` 时，如果程序此前没有识别到有效网址，会提示当前没有有效网址。
- 当前程序使用 `pending_url` 保存最近识别到的有效网址，因此按下 `o` 打开的是最近缓存的网址，不一定是当前画面中的网址。
- 二维码中包含的普通文本不会被当作网址打开，但仍可能作为识别内容参与记录。
- 打开网址前，建议确认其来源可信，避免访问恶意网站。

## 8. 识别结果保存

### 8.1 CSV 记录

文件名：`pyzbar_records.csv`

程序保存的字段如下：

| 字段   | 含义                  |
| ---- | ------------------- |
| 识别时间 | 条码满足保存条件时的系统时间      |
| 条码类型 | 例如 `QRCODE`、`EAN13` |
| 识别内容 | 解码得到的文本或数字          |

示例：

```csv
识别时间,条码类型,识别内容
2026-10-20 14:00:00,EAN13,6901234567892
2026-10-20 14:00:03,QRCODE,https://example.com
```

以上内容仅为格式示例，实际识别结果取决于摄像头读取到的条码。

程序使用 `utf-8-sig` 编码保存 CSV，有助于在常见的 Windows 表格软件中正确显示中文。

### 8.2 JPG 图片

图片默认保存到：

```text
pyzbar_images/
```

文件名使用当前时间生成，例如：

```text
20261020_140000_123456.jpg
```

文件名包含微秒部分，可以降低同一秒内保存多张图片时发生重名的概率。

保存的图片是程序调用 `cv2.imwrite()` 时的当前画面，其中可能包含识别框和文字标注。

## 9. 核心实现原理

### 9.1 摄像头读取

```python
cap = cv2.VideoCapture(0)
```

使用摄像头编号 `0` 打开默认摄像头。

```python
ret, img = cap.read()
```

- `ret`：表示本次是否成功读取画面。
- `img`：读取到的图像数据。

### 9.2 二维码与条形码解码

```python
results = decode(img)
```

Pyzbar 对当前帧进行检测和解码。每个识别结果都可以提供条码类型、内容和识别区域等信息。

### 9.3 EAN-13 校验

函数 `is_valid_ean13(code)` 主要执行以下步骤：

1. 检查条码是否为 13 位。
2. 检查内容是否全部由数字组成。
3. 根据 EAN-13 规则计算前 12 位的加权和。
4. 计算理论校验位。
5. 比较理论校验位和最后一位数字是否一致。

校验通过返回 `True`，否则返回 `False`。

### 9.4 多帧确认机制

```python
recent_frames = deque(maxlen=5)
```

`deque` 用于保存最近 5 帧的识别结果。超过容量后，最早的帧会自动移除。

每一帧都会将当前识别结果加入队列，即使这一帧没有识别到条码，也会加入一个空集合。

随后统计同一个条码在最近 5 帧中出现的次数：

```python
code_counts[code] = code_counts.get(code, 0) + 1
```

只有满足以下条件，条码才有资格进入保存流程：

```python
if count < 4:
    continue
```

这种方式可以降低偶然识别结果造成的误记录，但不能保证识别结果一定正确。

### 9.5 集合去重

```python
seen_codes = set()
```

程序使用集合保存已经成功处理的条码。

```python
if code in seen_codes:
    continue
```

如果同一种条码类型和相同内容已经处理过，就跳过保存。

只有图片和 CSV 日志成功写入后，程序才会执行：

```python
seen_codes.add(code)
```

需要注意：当前集合只存在于程序运行期间。重新启动程序后，集合会重新初始化，因此不能防止跨运行重复记录。

### 9.6 网址验证

```python
parsed = urlparse(data.strip())
```

`urlparse()` 用于解析二维码内容。

程序只接受同时满足以下条件的内容：

- 协议为 `http` 或 `https`。
- 存在主机名。
- 原始内容不包含空白字符。

满足条件后，返回网址；否则返回 `None`。

该检查只用于筛选网址格式，并不代表网址安全、真实存在或一定可以访问。

### 9.7 资源释放

```python
finally:
    cap.release()
    cv2.destroyAllWindows()
```

退出时释放摄像头资源，并关闭 OpenCV 创建的窗口。

`finally` 可以确保程序在正常退出或发生异常时，都有机会执行清理操作。

## 10. 当前版本的限制

- 需要摄像头和适当的光照条件。
- 多帧确认只能减少部分误识别，不能替代更严格的数据验证。
- 已处理条码集合只保存在内存中，程序重启后会清空。
- CSV 日志与图片分开保存，目前没有将图片路径写入 CSV。
- `pending_url` 会保留最近一次有效网址，即使该网址已经不在当前画面中。
- 网址格式检查不等于安全检查，不能保证识别到的网址可信。
- 当前版本主要针对单机实时识别，尚未实现数据库存储、历史记录查询或多设备协同。
